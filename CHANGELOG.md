# Changelog

All notable changes to the WälFlow project will be documented in this file.

---

## [0.2.0]

### Added

- **Neutral ports on boundaries**: Tank, pressure boundary and flow boundary (renamed from pressure source / flow source) have 1 to 8 neutral ports. The flow boundary supplies or draws a set flow, shared over its ports at common pressure, as an equal share or with its own flow per port; a draw has a minimum suction pressure and its pipes show positive flow. The port count sits below the name tag for all multi-port equipment. New flow boundary symbol (radial arrows, out for supply, in for draw); the tank liquid follows the rounded bottom. Older files are not converted.
- **Imperial / US Customary unit system**: Full bidirectional unit conversions across the entire application supporting standard engineering units (Pressure: `psi(a)` / `psi(d)`, Flow: `gpm`, Temperature: `°F`, Power: `HP`, Length: `ft`, Pipe Roughness & Diameter: `in`, Velocity: `ft/s`).
- **Global unit system selector**: Modern toggle switch in Sidebar Settings allowing seamless switching between Metric (SI) and Imperial (US Customary) unit systems, with persistence to localStorage and saved diagram files.
- **Pressure and flow sources** (`PressureSource` / `FlowSource`): Split the universal source into two separate components: a Constant Pressure Source (1 inlet + 1 outlet, solid concentric circle symbol) and a Constant Flow Source (1 outlet only, wave symbol), styled in dark theme colors.
- **Piping specifications and classes catalog (`/catalogue`)**: Replaced generic pipes with an industrial pipe classes architecture. Includes 4 standard built-in example specifications (`CS01`, `SS01`, `LT01`, `DX01`), size grids ($DN/NPS \to OD, WT, ID$), P-T ratings, and custom class CRUD management for `admin` and `pipe_manager` roles.
- **Direct inline pipe spec editing**: In-place inline page editing on the `/catalogue` page with live P-T rating point adjustments and dynamic internal diameter calculations, plus mini-dialog creation for new specifications.
- **Pipe class library import/export and seed management**: Full JSON library import and export for pipe class catalogs with duplicate conflict detection and optional example database seeding/deletion.
- **Project-level pipe specification management and search**: Real-time text search filter for project specifications, direct navigation to project settings via the sidebar gear (⚙️) icon, and project-level "Allow Manual / Custom Dimensions" Yes/No policy selector.
- **Manual pipe design parameters**: Dedicated "Inner Diameter" field with explicit Design Temperature and Design Pressure inputs for custom non-catalog pipes in the setup inspector.
- **Equinor TR2000 multi-spec batch importer**: Checkbox selection, Select All/Unselect All quick actions, solid sticky table header, live batch progress, and interactive duplicate conflict resolution dialog (Update, Import as Copy `(1)`, Skip, or Abort).
- **Reducer / expander fitting component** (`ReducerNode`): Added dedicated pipe transition fitting supporting both Concentric and Eccentric geometries, Crane TP 410 gradual contraction/diffuser form losses, Bernoulli dynamic pressure conversion, and analytical Jacobian derivatives.
- **Fitting standards and pipe schedules catalog** (`FittingStandard`): Implemented database model and REST API for ASME B16.9 factory-made wrought reducers (DN 20 to DN 600) and ASME B36.10M / B36.19M pipe schedules (STD, 40, 80, XS, 160).
- **Tabbed catalog interface** (`/catalogue`): Added subpage navigation tabs for Piping Specifications and Fitting Standards & Schedules with full catalog search, filtering, inline size editing, standard cloning, JSON library import/export, and default re-seeding.
- **Localized surface roughness**: Removed global canvas roughness; pipe friction factor is now calculated from localized roughness auto-mapped from material groups.
- **Pipe class and fitting library harmonization**: Full UI/UX harmonization between Piping Specifications and Fitting Standards tabs on `/catalogue` (elevated white cards, segmented pills, standardized top bar buttons, SVG icons, animated feedback toasts).
- **Control valve styles catalogue**: The `/pipes` page is now `/catalogue` with a third tab of control valve styles (IEC 60534-2-1 Table D.2 built in, manufacturer catalogues addable); the control valve inspectors pick a style or enter custom F_L / F_d. The example files use a fitting style for each control valve.
- **Frontend unit tests**: Vitest + jsdom + React Testing Library (`npm test`).
- **Pipe schedule presets for custom lines**: Integrated standard nominal size (DN15–DN600) and schedule (STD, 40, 80, XS, 160) quick-pick selectors with live outer diameter, wall thickness, inner diameter, and flow area previews in both inspector and DataList table.
- **Smart reducer auto-inheritance and mismatch detection**: Added 1-click auto-detection of connected pipe sizes and schedules on Reducer nodes, plus real-time mismatch warning alerts in the inspector and on canvas nodes.
- **Multi-standard support**: Seeded European DIN EN 10253-2 buttweld reducers alongside ASME B16.9 and mapped TR2000 specifications to their authorized default fitting standard.
- **Enhanced equipment categorization**: Reorganized sidebar into dedicated *Piping & Fittings* and *Distribution & Manifolds* sections.
- **AI agent skill** (`.agents/skills/pipe-classes`): Added dedicated skill documentation for AI pair programmers and LLM agents.
- **Catalog-driven reducer inspector**: Reducer sizes now come from the fitting standards catalog (incl. DIN EN 10253-2 and custom standards), follow the connected line's pipe class standard and wall thickness, and report missing data inline instead of guessing.
- **Fitting standard validation and restore**: Fitting standard create/update/import is validated (atomic import), deletion is blocked while pipe classes reference a standard, and admins can restore edited built-in standards to factory data.
- **Measurement taps and instruments**: An in-line Tap (zero ΔP, with a sensing pin) and rotatable ISA instrument bubbles (P, ΔP, Q, T, velocity, viscosity) with auto-tags, a pill shape for long tags, and LL/L/H/HH alarm indication. "Insert tap" on a pipe and "Add instrument" on a pin, a Measurements tab with per-case readings and editable limits, and warnings for unwired instruments. The API 614, Large Reference Network, Multi-PSV, Chilled Water and Thermal Management examples now carry instruments with alarm limits and upset cases that trip them. Signal lines stay attached to the pin of a rotated instrument.
- **DIN EN pipe dimensions**: New `DIN_EN_PIPE_SCHEDULES` standard (DIN EN 10220 normal / heavy wall and EN ISO 1127 stainless, DN15–DN600, same outside diameters as the DIN EN 10253-2 reducers). Reducers read their bores from the line's pipe class schedule standard (DIN EN reducers without a class use DIN EN), manual pipes get a dimension standard selector, and TR2000 classes with EN design codes are assigned DIN EN schedules.
- **Orifice calculation standard**: ISO 5167-2:2022 orifice pressure-drop calculation with a selectable calculation standard (Reader-Harris/Gallagher meter coefficient with §5.4 Formula (7) permanent pressure loss, plus the legacy `classic_cd` model), including a standard selector in the setup panel and a matching physics preview in the orifice detail panel.
- **Relief analysis**: Peak system pressure is now a solved steady state: pumps and sources are ramped until each relief device reaches its set pressure, replacing the old interpolation. The Peak view shows that state, the Relief Analysis Matrix shows per-device status, opening order, load and inlet pressures, and pumps/sources get a "Ramp during relief analysis" option.
- **PSV valve types and results**: Pressure safety valves get a valve type: conventional (opening shifts with backpressure, design superimposed backpressure input), balanced bellows, or pilot-operated (with an optional pilot sensing line to any sensing pin or tap). A new "Pop action – latching" mode stays open once popped. Statuses read Modulating (with lift %), Open, Cycling or Overcapacity. A cycling pop valve shows its average relief load and the inlet range reseat → set. Superimposed, built-up and total backpressure are reported with the 10 % (conventional) and 50 % (balanced) limits. The Multi-PSV example now shows pop vs. modulating behaviour and a pilot valve.
- **Max. discharge pressure**: PD pumps and flow sources get a "Max. Discharge Pressure" input (absolute, default 50 bar(a)), replacing the hidden 200 bar cap; above it the delivered flow drops (PD pump: internal relief to suction, flagged in the pump details).
- **PD pump drive type**: PD pumps get a drive type (fixed speed with motor-overload warning, or VFD power limit).
- **Enter key handler**: Global Enter key handler blurs numeric and text inputs on keypress, triggering validation and committing app updates.
- **Validation benchmark**: New example "Jeppson (1974) 7-Pipe Network" (Validation Benchmarks) with the published problems 2 (pump supply, = AFT Fathom Verification Case 63) and 3 (three reservoirs) as operating cases; a regression test holds WalFlow to the published flows, head losses and pressures. Second example "Jeppson (1974) 48-Pipe Network" (Ch. VI problem 3, two supplies, 28 demands) held to the published flows and friction losses.
- **Flow source withdrawal**: A negative set flow on a flow source draws that flow out of the network (a junction demand); the node shows it as a draw-off.
- **Junction**: One junction with 3 to 8 neutral ports replaces the mixer and splitter; a pipe connects to any port in either direction (tee, cross, header). The examples are converted; the Jeppson networks now show their four-pipe junctions as one node instead of chained tees.
- **Neutral ports**: Orifice, calibrated restriction, filter and measure point have two neutral ports (Port 1 / Port 2) instead of an inlet and outlet; pipes connect either way and the flow direction follows from the result. The solver treats each of these components as a link between two hidden port nodes, so every port has a solved pressure and can be sensed. Role ports (pumps, valves, relief devices) keep inlet / outlet; two outlets or two inlets cannot be joined. Older diagram files with these components no longer load; the examples are converted.

### Changed

- **Source and instrument symbol size**: The flow and pressure source symbols are 60 px like the pumps and valves (were 70 px), and their circles and the instrument bubble have the same diameter as the pump circle; the Jeppson examples keep their layout.
- **Signal lines**: Sensing/signal lines draw as one static dashed line in muted slate instead of two overlaid yellow/orange animated dashes; saved files render the new style unchanged.
- **Unit in every field name**: Node and pipe data fields carry their unit (`level_m`, `temperature_k`, `set_pressure_pa`, `opening_pct`, pipe `length_m` / `diameter_m`, …). Old 0.2 pre-release files are not converted; the file format stays 0.2. The field list per component now lives in `backend/simulation/equipment/<type>.md`.
- **Equipment documentation**: Every component document in `backend/simulation/equipment/` follows one 7-section standard (equations as implemented, thermal balance, parameters, model limits, benchmarks from the tests), with a new shared `relief_device.md`.
- **Canvas labels**: The tag and readouts below every component are centred on its symbol, however long they are.
- **UI/UX consistency pass**: One SVG icon set (Phosphor) replaces all emoji; Inter is bundled and a 7-step type scale (`--fs-*`) and warning colour tokens replace raw sizes and hex values; orange is reserved for the main action per area; tabs and segmented controls use dark teal; sentence-case labels and one set of component names (Pipe, Control valve, Drawing, "DN 20").
- **Header**: File menu (New, Open, Save `Ctrl+S`, Save as, Import, Export), document name with save state, and the last run time in the status pill; operating cases are created only in the Operating cases tab.
- **Smaller fixes**: Easier pipe selection (wider hit area), Admin Hub with fixed height and neutral stats, readable catalogue names and units in column headers on Piping Classes, "In force" badges on solver settings, the unused damping factor hidden, wider Help, tooltips and labels on icon-only buttons.
- **Tank fluid**: Tanks always use the system fluid; a hidden per-tank `fluid_type` in old files is ignored.
- **Settings levels**: Drawing (in the `.wlf`), Project and Global settings. Solver settings can be set on each level and are applied in the order Drawing, Project, Global (one tick box per level); fluid and ambient stay with the drawing. The unit system is now a per-user display preference stored with the account.
- **UX**: Resizable and collapsible data panel, fit-view after loading, right-click menus, empty-canvas hint, "-" instead of fake zeros before a run, positive pressure drops, tank and atmospheric pressure units, readable auto names, round pump chart ticks, and darker text colours (orange CTA now uses dark text) for WCAG contrast.
- **Model checks and status**: The drawing is checked before each run. Errors (unknown component type, several pipes on one port, empty drawing) block the run; warnings (open ports, self-loops, isolated components, circuits without tank or source) do not. A navbar status chip (connected, signed out, running, converged, failed, out of date) opens a panel that lists the checks and the notes of the last run, with a Show button for each item. A second pipe on a port is refused: use a splitter or mixer.
- **Result banners**: Solver errors, non-physical results (vacuum, below vapour pressure, temperature out of range), unsettled control loops and unreadable values show as dismissible banners. A run without equations is reported as "Nothing to solve" instead of "converged".
- **Per-tab drafts**: Each browser tab keeps its own local draft, so two tabs no longer overwrite each other. A draft left by a closed tab or an earlier session is offered when a new tab opens.
- **Faster editing**: Dragging or selecting a component no longer re-sends the graph to the solver, re-saves the draft or rebuilds every component; the data table and heatmap range share one code path.
- **Faster solve**: Simulations run about a quarter faster with identical results (fluid properties are cached, port state is stored without validation overhead, and the converged residual is not evaluated twice). Junctions and in-line component ports pass their pressure through the solve without a component lookup, and a pipe reuses its friction factor when the Jacobian asks at the same state (about 8 % faster, identical results).
- **Solver**: Temperature and pressure transport follow the port a pipe is connected to; the Jacobian of valves, regulators and thermal valves is differentiated from the model itself. The unused global pipe roughness setting was removed (pipes use their pipe class or their own roughness).
- **Examples**: Chilled Water Loop, Multi-PSV Protection, Parallel Pumps and Pump Comparison use a splitter or mixer where two lines met at one tank port (a port takes one pipe), so they run again. The status chip shows "Not run yet" after loading a drawing instead of the previous drawing's result.
- **Golden results**: A backend test solves every case of every shipped example and compares it with stored results (`WALFLOW_UPDATE_GOLDEN=1` refreshes them); Vitest runs on Node 25+.
- **Housekeeping**: Pydantic v2 API throughout, a smaller main bundle with lazy dialogs, Node 22.12 or newer required, and the app version kept in a `constants` file on each side (`backend/constants.py`, `frontend/src/constants.js`).
- **Out-of-date results**: The data lists are no longer greyed out and the canvas banner is gone; the navbar chip shows the state.
- **Dialogs**: All native alert, confirm and prompt dialogs are replaced by toasts and in-app dialogs (focus stays inside and returns afterwards). New operating cases ask for a name.
- **Modal theme**: Login, Save As, New Drawing, Help & Shortcuts, Project Manager, Admin Setup and Admin Hub dialogs use the global light theme tokens and generic classes defined in `index.css`.
- **Help**: Rewritten for the current UI, with a new Model & Limits tab (steady state only, Darcy-Weisbach friction, fluid ranges, simplified valve viscosity correction). Help button in the navbar; `Shift + ?` opens it.
- **Pipe classes**: Explainer on the catalogue page (what the solver uses and what is informational only). The schedule dropdown lists only the schedules the catalogue has for the selected size.
- **Accessibility**: All dialogs have a dialog role, a title label, a focus trap and focus return; form labels are tied to their fields; clickable elements work with Enter and Space; visible focus rings; case and heatmap controls expose their state as text.
- **Shortcuts**: Shortcuts no longer act behind dialogs or block copying selected text. Welcome canvas and the large reference network are listed as examples; example notes say what to check.
- **DataList matrix**: The batch matrix table selects Piping Specifications rather than pipe schedules.
- **Orifice detail panel**: The chart uses dynamic X and Y axis scaling so it stays usable for small values. Its pressure-loss curve matches the solver by reporting the solver-effective connected-pipe diameter and calculation standard in simulation telemetry, so curve, beta ratio and operating point use the same geometry.
- **Loading overlay**: Modals close immediately and the canvas loading overlay shows during database fetches, so wave animations run smoothly while the network is idle. `FlowDropMark` nests its flow lines in the pulsating container and pauses SVG animations when hidden to save CPU.
- **Session drafts**: Local draft validation uses the dynamic `FILE_FORMAT_VERSION` constant instead of a hardcoded string.
- **Fluid properties and correlations**: Tabulated water, seawater and glycol properties, Walther oil viscosity, RVP-based fuel vapour pressure, fluid temperature ranges (unknown fluid ids are an error), NPSHa/NPSHr check with editable margin, filter reference viscosity, low-Re orifice Cd, Churchill pipe friction, ISO 5167 / heat exchanger / flow source limit warnings.
- **Pipe defaults**: New pipes default to DN50 STD; pipes from older files show as Manual with their matching size or custom inner diameter. Undo history resets on load, covers add/connect/delete/paste/rotate, and is blocked on read-only drawings, which also block delete, paste and rotate.
- **Centrifugal pumps**: Rated in head (m) with an efficiency input (pump only, excl. motor); a stopped pump acts as a flow resistance and a running pump resists reverse flow. Older files need the rated head entered once; examples are converted.
- **Pump power**: The pump power KPI uses actual shaft power.
- **Pressure regulators and back-pressure valves**: They settle on their setpoints (also PRV + BPR in series) regardless of settings or run history, close tight (lock-up) when nothing draws flow, and the solver reports unreachable setpoints, non-converged runs, impossible pressures (vacuum) and circuits without a tank or pressure source instead of showing a clean result.
- **Relief devices**: Set and burst pressure are entered in gauge (barg / psig) and open when the inlet gauge pressure reaches them (older files need the value re-entered; examples are converted). "Forced Open" now works, pop valves respect blowdown and report "cycling" when oversized, capacity % refers to the rated flow at 10 % overpressure, and the relief matrix re-solves with the newly chosen forced state.
- **Control valve sliders**: Sliders on the canvas respect the active operating case: in a non-base case the opening is stored as a case override (with the case badge) instead of silently changing the base case.
- **Data integrity**: Results are no longer saved in files, drafts or cloud saves (files shrink by up to 95 %; a loaded diagram is solved automatically) and are labelled "out of date" once the diagram changes; every load path (file, drop, example, cloud, project, draft) checks the file format and structure with one clear message, and a render error shows a recovery screen instead of a blank page. Inputs keep their exact values when you click through them, accept 0 where it is valid, and solver settings are range-checked; heat exchangers use their rated pressure drop (0.5 bar default, Chilled Water example flow drops 16 %), NaN results no longer drop the reply, and catalogue wall thicknesses (10S, DN400) are corrected.
- **Solver accuracy**: No more phantom flow in low-loss pipes (tolerance setting now takes effect), safe shared warm-start cache, Levenberg–Marquardt option solves all examples. API 682 example uses a centrifugal pump so both regulators work.
- **Security and deployment (B3)**: The login rate limit can no longer be bypassed with a spoofed `X-Forwarded-For` (`WALFLOW_TRUSTED_PROXY_HOPS`); the compose file requires `WALFLOW_SECRET_KEY` (see `.env.example`; everyone is logged out once on upgrade), publishes the backend on 127.0.0.1 only and passes configurable limits; simulations (WebSocket and `/batch`) have a size limit, a solve timeout and a concurrency cap; anonymous users may simulate while collaboration needs a login and access to the diagram; the last administrator is protected, disabled users lose access immediately and `pipe_manager` can be assigned in the Admin Hub; edit locks are released when the tab closes, standalone-diagram locks are owner-only, a save is refused when the diagram changed elsewhere, and co-editors get one non-blocking banner instead of a reload prompt after every autosave.
- **Pipe class validation**: Pipe classes reject unknown fitting standard references, and pipe class library import keeps reducer / schedule standard codes.
- **Test suite and CI**: Backend tests restructured into `unit / scenarios / regression / api` layers with audit IDs as pytest markers and an isolated temporary database; GitHub Actions CI (backend tests, frontend lint, tests and build) that must pass before Docker images are published; it runs on release tags only.
- **Test strategy** (`walflow-qa` skill, replaces `TESTING.md`): Test pyramid with a bug-fix decision tree that favours properties and reference rows over new test functions; hypothesis property tests check every equipment model's contracts (zero flow, flow-direction loss, monotonicity, side-effect-free evaluation, pipe and pump derivatives) over generated parameters and fluids; `requirements-dev.txt` for test dependencies. Network property tests solve generated series-parallel networks and check mass and energy balance, pressure along the flow, dissipation heating, order independence and warm start. Redundant tests merged into parameter tables or deleted after a Cosmic Ray mutation run showed no coverage is lost; mutation testing documented in the skill (`backend/cosmic-ray.toml`). Frontend tests stay lean; every shipped `.wlf` file round-trips through export and the file check.
- **`/catalogue` toolbar**: Library actions (New, Import from TR2000, Import, Export, Restore defaults) moved from the top bar into the detail card next to Clone / Edit; New and Edit buttons are no longer orange.
- **Fitting standards editor**: Pipe schedule matrices are fully editable (DN, NPS, OD, wall thickness per schedule, add / remove sizes and schedule columns; ID = OD − 2·WT). Reducer rows fill NPS and OD from the DN and recalculate the cone angle. Name, description, standard group and reducer type are editable, values follow the unit system, and admins can edit built-in catalogs.
- **Fitting standard names**: The catalog shows the name; the code is shown as a small identifier and is derived from the name when cloning or creating a standard.
- **Equipment cleanup**: The unused `is_flow_boundary` solver flag is removed, and the PSV no longer accepts the old `rupture_disc` action mode (use `Pop action – latching`). Analytical pressure-drop derivatives that the solver never used are removed; it differentiates those components numerically, and pipes and pumps keep theirs.
- **Standards register**: The standards and literature cited by the equipment documents are collected in `docs/STANDARDS_REGISTER.md` with current editions and a status per claim (all unverified until checked against the source). Section 2 of each equipment document is a claim table, and the `standard-verification` skill describes how a supplied standard is checked.
- **Solver speed**: Each hydraulic solve updates the fluid properties once instead of twice, which brings solve times on large networks back to their earlier level.
- **Mass balance at nodes**: Every node now conserves mass flow instead of volume flow, so the volume flow rises where fluid is heated or mixed hot (about 2.8 % for water heated from 10 to 80 °C) and falls where it is cooled. Every component's curve is evaluated at its inlet volume flow.
- **Solver topology tables**: The ports at both ends of every pipe are looked up once per solver and shared by the stagnant-section pressures and temperatures, the fluid-property passes and the mixing solve, instead of being rebuilt on every pass. Results are unchanged.
- **Total pressure at nodes**: The solver balances total pressure at nodes and reports static pressure at ports, so a junction between pipe sizes no longer gains kinetic energy and networks with a reducer in a loop reach a steady state. NPSHa includes the suction velocity head. A dead branch reads the static pressure of the line it tees off. Results shift slightly where pipe velocities differ at a junction.

### Fixed

- **Canvas usability**: Pasted components are offset and get the next free tag; a dropped component is centred on the cursor; equipment search finds tag abbreviations (PCV, TCV, PSV, PRV, FCV, NRV, HX); loading a drawing clears the selection so the inspector no longer shows the previous drawing.
- **Console and accessibility**: No WebSocket error logged on page load; inspector charts no longer warn about zero size; Pipe Network List fields have accessible labels and drawing-list buttons are no longer nested.
- **Cloud drawing lock and restore**: Opening a free cloud drawing (new, opened or restored after a reload) checks it out automatically; the read-only notice has a Check out button or names the user editing it. After a reload the local draft is only restored, with its notice, when it holds unsaved changes; if the cloud copy changed meanwhile, you choose between the cloud version and the local copy instead of the draft overwriting it. No re-upload after opening a drawing; the status reads "Saved to cloud HH:MM".
- **Cloud save safety**: An edit made just before opening another drawing is saved to its own drawing instead of lost; choosing "Load cloud version" after a reload no longer saves the local draft over it, and the discarded draft is not offered again; opening a drawing no longer saves it; an expected save conflict is no longer logged as an error.
- **One checked-out drawing per user**: Opening another drawing saves and checks in the previous one; the same drawing open in a second tab is read-only there. A lock is released after 30 minutes without activity, or 60 s after the connection drops (kept on reconnect), and expires 3 minutes after its last heartbeat instead of 15. The sidebar padlock no longer checks out unopened drawings, and a project drawing's content is saved only by the tab that checked it out. A tab whose lock lapsed (sleep, lost connection) takes the drawing back if it is still free, but never one you have since left for another drawing.
- **Lock status at a glance**: Drawing rows show an "Editing" badge for your drawing and a padlock with initials for someone else's, and the navbar shows "Editing" or who is editing since when; a drawing open in your other tab says so, and the badges refresh when you return to the window. The saved time, the restore and conflict dialogs and the selected folder row follow the drawing you open.
- **Flow precision**: Flows below 10 show 2 decimals, so small flows no longer look unbalanced across a component.
- **Unknown component types**: The backend rejects a component of unknown type (e.g. the removed mixer and splitter) with an input error naming it, instead of failing the solve with an internal error.
- **Pipes with reverse flow**: Friction uses the density and viscosity of the end the flow enters by, not the drawn inlet, so a heated viscous line gives the same result whichever way it is drawn.
- **Components with reverse flow**: Valves, regulators and other components evaluate their pressure drop with the fluid of the port the flow enters by, not always the inlet.
- **Pressure controllers with temperature-dependent fluids**: The extra solves that measure a controller's sensitivity hold the fluid properties fixed instead of recalculating them, so systems with controllers and a TCV settle in fewer iterations (shipped examples about 17 % faster overall) and a TCV ends closer to its setpoint (results change by up to 0.2 %).
- **Control valve viscosity correction (IEC 60534-2-1)**: The linear control valve, remote control valve and three-way TCV use the Annex A Reynolds number factor, sized from the connected pipe, so viscous low-flow cases give the laminar pressure drop (previously up to two orders of magnitude too low).
- **3-way TCV control loop**: The mix ratio no longer cycles when the outlet temperature responds steeply (e.g. viscous laminar paths), and a TCV that misses its setpoint is reported as not settled instead of converged.
- **Orifice losses (ISO 5167-2)**: The orifice's Reynolds validity limit above β 0.56 is 16 000·β² instead of 16 000. The calibrated restriction, check valve orifice, reduced-bore rupture disc and classic orifice model use the permanent loss of ISO Formula (7) instead of 1 − β² (results change by up to 2.5 %).
- **Heat exchanger**: Reverse flow now cools the stream that actually enters. The rated pressure drop is reproduced in the system fluid at the design inlet temperature (previously only for water), and the rated UA no longer drifts with the operating temperature.
- **Mixer with reverse flow**: An inlet that carries flow back into its pipe reports density and viscosity at the mixed temperature (previously the default 1000 kg/m³ and a stale viscosity).
- **3-way TCV mixing**: The mixed outlet temperature follows the enthalpy balance with temperature-dependent heat capacity, like the mixer (up to about 0.9 K warmer in oil).
- **Pump heat**: Shaft power and waste heat use the entered efficiency down to 1 % (previously clamped at 5 % and 10 %). A pump driven by the fluid (braking) turns its whole pressure drop into heat, like a throttle. A running pump with reverse flow still draws shaft power.
- **Check valve with orifice**: Above cracking, seat and orifice now share one pressure drop, and the seat gets the viscosity correction of the plain check valve. A section shut in behind it takes the pressure of the other side, since the orifice always connects both.
- **Calibrated restriction**: Calibrates with the connected pipe bore and the system fluid from the first solver iteration, and only again after a change. A calibration temperature of 0 °C is kept instead of becoming 45 °C; an invalid calibration point (no flow, no pressure drop) is reported as an input error.
- **Linear control valve**: An opening below 0.1 % now closes the valve, like 0 %, instead of acting as 0.1 %.
- **Check valves**: The cracking pressure is labelled `Cracking ΔP` in bar (psi), as a pressure difference, not barg (psig).
- **Tank**: A new tank starts at 1 m level, the same default the backend uses for files without a level.
- **Pipe and reducer friction**: A pipe roughness of 0 is now a smooth wall instead of 0.045 mm. The reducer uses the same Churchill friction factor as the pipe, with a consistent derivative.
- **Splitter mixing**: When the inlet and one outlet both feed a splitter, the remaining outlet now carries the energy-balanced mixed temperature instead of the inlet temperature.
- **Pressure in stagnant branches**: A section shut in by a stopped PD pump, a closed check valve or a closed relief device now takes the pressure of its leak path (usually the pump suction) instead of a value that changed with the solver method, and is flagged `stagnant` in the telemetry.
- **3-way TCV loop**: The thermal valve now settles within 0.01 K of its setpoint, or exactly at its end stop, independent of the start and in fewer iterations; the unused damping factor setting is removed (older files are still accepted).
- **Custom reducer length in imperial units**: A transition length entered in inches is stored correctly (it was converted a second time as feet); the inspector shows the length the solver uses, and empty or zero reducer dimensions are rejected.
- **Inspector defaults match the solver**: A 0 m pipe is shown as 0 m (not 25 m) and a tank without a level as 1 m (not 0 m). Reducer roughness of 0 mm is kept as smooth instead of falling back to 0.045 mm, and negative reducer roughness is rejected.
- **Batch solve URL**: The batch solve matrix no longer uses a hardcoded `localhost` backend URL; it uses the relative `/api/simulation/batch` endpoint, fixing the CORS / `ERR_FAILED` error behind a reverse proxy (e.g. Cloudflare).
- **Canvas loading race**: Fixed loading overlay race conditions on synchronous example diagrams (e.g. API 614) by deferring heavy state updates to the next event loop tick. The overlay now sets `pointerEvents` correctly to block clicks during loads.
- **TR2000 client**: Response parsing unwraps dictionary envelopes (`getPlant`, `getPCS`, `getPipeSize`, `getTempPressure`), restoring live plant querying, spec search and specification synchronization.
- **TR2000 mapping**: Design-code mapping to DIN EN reducers matches whole words only; reducer nodes with null geometry no longer crash the graph parser.
- **Project specification filter**: Re-enabling all specifications now clears the restriction in the database, and the active project context takes effect immediately on the canvas edge inspector and DataList matrix table.
- **Page refresh**: Fixed canvas state recovery loss and database synchronization detachment on refresh, and the development-only empty canvas caused by React StrictMode clearing the hydration timeout.
- **Pressure source**: `PressureSource` now initializes the Dirichlet pressure boundary correctly.
- **Flow source solving**: Dead-end leaf pruning and DFS reachability handle `FlowSource` boundary nodes, and pressure drop and mass-balance constraints work for 2-port inline nodes (such as flow sources and pumps) with unconnected inlet ports.
- **Warm-start cache**: Lookup collisions are avoided by including active node pressure-boundary states in the topology key.
- **Reducer losses**: Crane TP 410 gradual-contraction angle ranges were swapped, overstating losses by about 57 % for standard reducers; the reducer Jacobian sign under static pressure recovery is also fixed.
- **Imperial and input handling**: Imperial pipe sizes were stored 39× too small; fixed misaligned DataList columns (added sortable Name column), numeric inputs reformatting while typing (now commit on blur/Enter, Esc reverts), cloud-load cancel leaving the wrong diagram active, and examples/files loaded over an open cloud drawing overwriting it.
- **PD pump flow**: PD pumps no longer pass unlimited flow when fed from a pressurised header.
- **Throttling heat**: Fixed throttling heat missing in valves, check valves and relief devices, TCV pressure drop using water viscosity, and inconsistent results when the control loop hits its iteration limit; physics tests now assert against independent references.
- **Simulation engine error**: Diagrams with a PD pump (e.g. Multi-PSV Protection example) failed because pump warning flags broke the result payload.
- **Orifice in reverse flow**: Used default water density/viscosity for its pressure drop and throttling heat instead of the actual fluid's.
- **Simulation correctness**: Heat exchanger pressure drop now reverses with flow direction; relief analysis always restores user-set device states if a solve fails; empty or non-positive pipe and heat exchanger inputs now give readable input errors instead of generic failures.
- **Access control and data integrity**: Removed project members can no longer delete diagrams; check-in requires diagram access and only announces a lock release when one was held; deleting projects or users with invitations works, and deleting a user hands their shared project diagrams to a project owner; invitation passwords are no longer trimmed and expiry is bounded; the admin user list shows the creation date; a deleted user's token now returns 401.
- **Library imports and TR2000**: Pipe class and fitting standard imports no longer fail on repeated codes or malformed entries in one file; TR2000 requests validate the PCS code and revision, verify TLS certificates by default (`TR2000_VERIFY_TLS=false` to disable behind a re-signing proxy), and no longer expose upstream error text.
- **Performance and locking**: Property propagation in the solver scales linearly with diagram size, diagram lists no longer load the diagram contents, and Redis edit-lock acquisition is atomic.
- **Example pipe specs**: The Nominal size selector and dimension summary were missing on pipes of the example drawings because the examples referenced the piping spec by code (`CS01`) while the catalogue matches by id. Pipe specs now resolve by id or code, the examples use the catalogue ids, specs missing from the catalogue show the stored dimensions with a notice, and the DN label is the same before and after a spec change.
- **Pipe schedule catalogs**: ASME B36.19M stainless schedules (5S/10S/40S/80S) are now their own catalog; the B36.10M catalog gains Sch 10/20/30/60 and drops the B36.19M label. Catalog data lives only in the database (seeded on first start; Restore Defaults adds missing catalogs and lets admins reset edited built-ins); the frontend copies are removed.
- **Pipe classes reference the catalog**: A class selects one or more pipe dimension catalogs and reducer catalogs. Size rows store catalog + DN + schedule and read OD/WT from the catalog, so catalog edits reach every class using them; a catalog size in use cannot be removed. Sizes no catalog lists are marked as custom rows. Existing classes are converted on startup.
- **Pipe class integrity**: Size rows are checked (duplicate DN, catalog selected for the class, DN and schedule listed) and P-T curves against the design temperatures; deleting a class removes it from project allow-lists; example classes are seeded only on a fresh install and both seed paths create identical classes.
- **Pipe class editor**: The schedule list offers only the class's catalogs, grouped by catalog, with the same names as the catalog view (e.g. Sch 10S, STD); OD/WT come from the catalog; default corrosion allowance and design temperatures are editable; negative P-T temperatures can be typed; values follow the unit system.
- **Reducers on pipe class lines**: Reducer standards are limited to the class's reducer catalogs, and each end reads its wall from the catalog of the class size.
- **TR2000 sync**: Revision date is stored, NPS above 4" map to DN = 25 × NPS, unreadable sizes are skipped, material roughness matches whole words, and sizes matching a catalog become references (others custom rows).
- **Naming**: "Pipe specification" / "Piping spec" is now "Pipe class" throughout the app; project allow-lists that store class codes show and toggle correctly in the sidebar.
- **Expander next to a tank or pressure source**: Tanks and pressure sources now hold fluid at rest, so a pipe leaving one takes the entry velocity head and a short source → expander → tank line solves.
- **Parallel control valves on one sensing point**: Valves holding the same point with the same setpoint share one opening; with different setpoints the highest PRV (lowest BPR) regulates and the others close, instead of an arbitrary split or no convergence.
- **Detail chart axes**: The valve, filter and orifice detail charts show numbers on the pressure axis (the unit had pushed them out of view), a round flow axis end instead of a long decimal, and each unit once as an axis title.
- **Valve detail chart curves**: The control valve, remote control valve and regulator charts draw the pressure drop the solver uses (with the Reynolds number factor and the valve style), sent with the results, so the curves pass through the operating point and differ between trims.
- **Reported pressures match the reported fluid properties**: The solver ends on a hydraulic solve with the final densities and viscosities, so viscous pipes no longer show a small pressure rise and pressure controllers are judged on the reported pressures. Orifices and calibrated restrictions report outlet density and viscosity at the warmed outlet temperature.
- **Temperature of dead legs**: Ports without flow (behind a closed check valve, removed dead legs) take the temperature of their nearest live neighbour or boundary instead of the 20 °C default, so a repeated (warm-started) run reports the same temperatures as the first.
- **Property loop near a flow reversal**: When a branch close to zero flow makes the flow solve and the temperature update cycle, the solver now damps the flows it propagates temperatures with until both agree, instead of stopping after 100 iterations with flows and temperatures from different states.
- **Temperatures in loops of junctions**: Junction mixing is solved for all nodes at once, so a recirculation loop with a small through-flow reaches the temperature of its supply instead of stopping near the 20 °C start value. A pump-driven loop with a small through-flow now heats up to its energy balance instead of stopping early because each property pass changed little. Flows below the solver's noise level (1e-9 m³/s) no longer shift a junction's mixed temperature.
- **Pressures behind a stiff micro-flow component**: A nearly closed valve passing ~1e-8 m³/s no longer shifts a few Pa of its drop into the next pipe's reported drop; component drops are reported at the flow the solve used.
- **Fitting standards edits**: Changing a reducer DN no longer leaves a stale OD and cone angle; saved schedule IDs and cone angles are recalculated by the server; unsaved fitting edits are no longer lost silently when switching tabs; the pipe class tab picks up catalog edits without a reload.
