# Phase 3: User Friendliness

**Date:** 2026-10-13
**Method:**
- Live walkthrough in Chrome against the local dev servers (Vite on :5173, FastAPI on :8000).
- The backend was restarted with `WALFLOW_REQUIRE_WS_AUTH=false` (user's choice), so all runs were anonymous.
- Native dialogs were stubbed in the tab so automation could continue: `confirm` answered OK, `alert` was logged.
- Viewport 1920×855 CSS px.
- Code reading backed up items that could not be run.
- Persona: a process engineer opening WalFlow for the first time.

**Not exercised live:**
- 3.7 cloud save, lock and share.
- 3.10 admin flow.
- Both need a login and were reviewed from code only.
- Export and import were not run, because they need a file download.
- F2-02 is therefore still unconfirmed.

**Phase 2 items confirmed in the browser:**
- **F2-01 (imperial pipe diameter):** with Imperial on, picking DN 50 STD in the inspector gives "ID 0.052 in, Area 0.00 in²". Flow drops to 0 gpm and the pump sits at shut-off (+87 psi). No warning appears. Switching back to Metric does not repair the pipe; the size has to be picked again.
- **F2-07 (stale results):** a freshly created Case 2 shows Case 1's results with no marking.
- **F2-08 (reformat while typing):** typing `25.5` into Ambient Temp (°C) leaves `2.1` in the field.

## 3A. Task walkthroughs

### 3.1 First launch
- A new visitor gets `GreetingCanvas.wlf`: a welcome note plus a starter tank–pump–valve–tank circuit with three cases. The purpose is clear and no login is needed to look around.
- Friction, ranked:
  1. In the default configuration (`WALFLOW_REQUIRE_WS_AUTH=true`), "press Run Simulation" in the welcome note leads to a native alert: "Simulation engine is not connected. Please ensure the backend is running and you are logged in." Nothing on screen says a login is needed before then (F3-03).
  2. The greeting canvas can't be reopened from Library & Examples (F3-15).
  3. The navbar shows `v0.2.0 • Beta` while AGENTS.md says 0.1.6 (F3-19).

### 3.2 Build tank → pump → orifice → tank
- Building the circuit took about 12 actions: four drags, three connections and one run. Search ("orifice") and drag-and-drop work smoothly, and port colours (blue in, red out) make connecting obvious.
- Friction:
  1. New Drawing opens zoomed far out, so dropped nodes are tiny until you press fit-view. Loading an example keeps the previous viewport, and the canvas looked empty (F3-08).
  2. The empty canvas has no "drag components here" hint (F3-18).
  3. New pipes are shown as **DN 15 (½") / CS01** but simulated at 52.5 mm (DN 50). The inspector card contradicts itself: "DN15 (½") • STD – OD 60.4 mm, ID 52.48 mm" (F3-02).
  4. Defaults: tank 40 °C while ambient is 20 °C; labels like `CENTRIFUGAL_PUMP_541` (F3-13).
  5. The routine success message "New local draft initialized." appears as a native alert (F3-06).

### 3.3 Understand a result
- The canvas shows the pump ΔP and flow and the orifice ΔP. The pipe inspector's Results tab is good: up/downstream pressure, ΔP, velocity, Reynolds number and gradient, all with units.
- Friction:
  1. **Pipe Network List headers are shifted by one column** (F3-01). Example: Suction "dP (bar(d))" shows 4.48, which is actually the velocity in m/s. "NPS / Size" shows 20.0, which is the temperature.
  2. Pressure drop is shown as a red negative number ("-1.34 bar(d)"), which reads as an error (F3-11).
  3. Velocity cells turn orange above 2.5 m/s and red above 4 m/s, with no legend (F3-05).
  4. Pump chart axis labels are raw floats ("248.07649802880613 L/min", "6.6000000000000005 bar(d)") and the y-labels are clipped (F3-14).

### 3.4 Failed or degenerate simulation
- Deleting the orifice→tank pipe left the orifice outlet open. Run → Stats said "**SOLVER CONVERGED – System is balanced**", 0 equations.
- The suction pipe showed 1.21 → 7.21 bar(a), a 6 bar rise at zero flow. No warning named the open port (F3-04).
- The run status appears only in the Stats tab; the main view never shows converged or failed.
- A non-converging case wasn't triggered live. The Phase 1 runs cover the solver side; the message path is a native alert (F3-06).

### 3.5 Units and fluid
- The unit switch sits under Settings → **Global**. That sub-tab contains only units and version info; the fluid and solver settings are under **Drawing** (F3-12).
- In Imperial, pump, pipe and table values convert. Tank nodes still show "2.00 m" and "40.0 °C" (F3-11).
- Atmospheric pressure is entered in **Pa** next to fields in bar and °C (F3-11).
- The fluid picker has 23 fluids with a one-line explanation. Its effect on viscosity and density is not shown anywhere until after a run.

### 3.6 Operating cases
- "+ New Case" creates "Case 2" at once and makes it active, without asking for a name.
- The inspector's "Case Variable / Overridden / Reset" badges, and "Global" on non-case fields, are clear and well designed.
- The Operating Cases Matrix shows KPIs side by side with deltas and percentages, plus rename, delete, Switch and Batch Solve. This is the strongest part of the UI.
- Friction:
  1. The new case shows the previous case's results unmarked (F2-07).
  2. Pump "Inactive (Off)" with equal tank heads still shows 0.3 L/min (F3-16).

### 3.7 Save, reload, export/import, cloud
- Local autosave works: the draft survives reload, and the "Restored Session Draft" toast is good.
- The Workspace tab explains "Cached in browser storage. Log in and save to cloud."
- Cloud save, lock and share were not run (no login); see F2-02, F2-11 and F2-25 for the code-level issues.

### 3.8 Pipe classes
- The `/pipes` page is clean: class header (standard, grade, rating, roughness, design temperature) and a size table (DN, NPS, OD, WT, schedule, ID, corrosion allowance). The diagram state survives a round trip to this page.
- Friction (F3-17):
  - Nothing explains what a class does in the simulation. Only the ID and roughness are used; the rating, design temperature range and corrosion allowance are shown but never checked against results.
  - The "TR2000" badge is unexplained.
  - The test entry "CS02R asdf" appears in every dropdown. It is local data, not a code issue.

## Findings

### S1

**F3-01 – Pipe Network List: every result sits under the wrong header.** [DataList.jsx:847-856](../../frontend/src/components/panels/DataList.jsx#L847-L856)
- **Problem:** rows have 13 cells (drag handle, type, **name input**, flow, …), but the header has 12. The name column has no `<th>`, so each value appears one column right of its label.
- **Live example:** Suction row reads "dP (bar(d)) 4.48" (actually the velocity in m/s), "P Start 0.128" (actually ΔP), "NPS / Size 20.0" (actually temperature in °C).
- **Impact:** this is the main results table and the CSV export's visual counterpart. An engineer reading it gets wrong pressure drops and pressures.

**F3-02 – New pipes are displayed as DN 15 / first pipe class but simulated at DN 50.** [App.jsx:907-908](../../frontend/src/App.jsx#L907-L908), [DataList.jsx:869-873](../../frontend/src/components/panels/DataList.jsx#L869-L873)
- **Cause:** `onConnect` creates pipes with `diameter: 0.05248` and no `standardDn` or `pipe_class_id`. The table and inspector then fall back to the first class (CS01) and its first size (DN 15).
- **Symptom:** the inspector card shows "DN15 (½") • STD" with OD 60.4 mm and ID 52.48 mm.
- **Impact:** the user believes the pipe is ½" when the solver uses 2". The results (1.6 m/s at 207 L/min) contradict the displayed size, and nothing marks the size as unset.

### S2

**F3-03 – Simulation needs a login by default, but the app invites anonymous users to run.**
- **Cause:** `WALFLOW_REQUIRE_WS_AUTH` defaults to true ([main.py:101](../../backend/main.py#L101)); `start.ps1` and docker-compose set it to false.
- **Symptom:** an anonymous user on a default deployment sees the welcome note "press Run Simulation", then gets a native alert. No connection or login status is shown before that.
- **Decision needed:** either let anonymous users simulate, or show "Sign in to simulate" on the button and in the note.

**F3-04 – "Converged / System is balanced" reported for a degenerate network; no topology warnings.**
- **Setup:** the orifice outlet was left open.
- **Result:** 0 equations, "converged". The suction pipe showed a 6 bar rise at zero flow.
- **Missing:** a pre-run check for unconnected ports and no-flow paths. Related to F2-19.

**F3-05 – No engineering plausibility warnings.**
- **Not flagged:**
  - A pump at 2× rated flow, near run-out.
  - Pipe velocities of 7–8 m/s (in shipped examples too).
  - Pipe class rating or design temperature exceeded.
  - Fluid temperature outside property validity.
- **What exists:**
  - The cavitation flag.
  - Velocity colour thresholds (2.5 and 4 m/s, [DataList.jsx:968](../../frontend/src/components/panels/DataList.jsx#L968)), with no legend and no distinction between suction and discharge.
- **Impact:** users can rely on bad numbers.

**F3-06 – 86 native `alert`/`confirm`/`prompt` dialogs.**
- **Where:** App.jsx (16), ProjectManagerModal (21), PipeClassesPage (20), Sidebar (10), and others.
- **Effects:**
  - They block the page and don't match the design system.
  - They are used for routine success messages ("New local draft initialized.") and for the only "not connected" error.
  - They also blocked browser automation in this audit.
  - New cases are created without asking for a name.

**F3-07 – Help is hard to find, outdated, and doesn't explain the model's limits.**
- **Out of date:** the guide refers to a "Calculate" button, a "Global Settings accordion", ambient temperature in K, setpoints in Pa, and a "top dropdown" of templates with old names.
- **Rendering:** it shows raw LaTeX (`$bar(d)$`, `$^\circ C$`).
- **Missing:** no section on assumptions or valid ranges, in-app or in the README.
- **Access:** only a small "?" icon or Shift+?.
- See [HelpInfoModal.jsx:310-380](../../frontend/src/components/modals/HelpInfoModal.jsx#L310-L380).

**F3-08 – The canvas gets too little space, and view fitting is missing.**
- **Space:**
  - The data panel is a fixed 350 px with no collapse or resize ([DataList.jsx:389](../../frontend/src/components/panels/DataList.jsx#L389)).
  - The inspector overlays the right side of the canvas.
  - At 1920×855 the canvas is 1280×470 px.
- **Fitting:**
  - Loading an example keeps the old viewport, so the example looked empty.
  - New Drawing starts zoomed far out.
  - At fit-view the labels are unreadable.

**F3-09 – Contrast below WCAG AA on primary elements.**
- White text on `#FA8507` (Run Simulation and all primary CTAs): 2.49:1.
- Orange text on white (active tabs, ΔP values): 2.49:1.
- Red `#EF4444` text on white at 11 px: 3.76:1.
- Velocity severity is conveyed by colour only.
- Changing the CTA needs a design decision, because orange is the brand accent.

**F3-10 – Placeholders look like real results before a run.**
- **On nodes:** "+0.00 bar(d)", "0.0 L/min" and a red "-0.00 bar(d)".
- **In the table:** "P Start 0.00 bar(a)" (absolute zero, which is impossible) and "Temp 0.00 °C".
- **Missing:** a "not calculated" state such as "—". Related to F2-07 and F2-20.

### S3

**F3-11 – Units and notation inconsistencies.**
- Tank nodes don't convert in Imperial.
- Atmospheric pressure is in Pa.
- `bar(d)` is non-standard (use ΔP in bar).
- Drops are shown negative and in red.
- BPR and PRV labels say "Set: 5.0 bar(a)", while the example labels say "Upstream Set: 5 bar", leaving gauge vs absolute unclear.

**F3-12 – Settings layout.** The "Global" sub-tab holds only units and version info; fluid and solver settings sit under "Drawing". The unit choice is stored both per browser and in each diagram's `globalSettings`.

**F3-13 – Defaults and labels.**
- Tank temperature defaults to 40 °C while ambient is 20 °C.
- Auto tags look like `CENTRIFUGAL_PUMP_541`.
- The pipe inspector title shows the internal edge ID instead of the name tag.
- New pipes are 25 m long.

**F3-14 – Pump curve chart formatting.**
- Axis ticks are raw floats and the y-labels are clipped.
- "Load Factor — %" shows with no explanation.
- See [PumpDetails.jsx](../../frontend/src/components/details/PumpDetails.jsx).

**F3-15 – Example library.**
- The greeting canvas is not listed, so it can't be reopened.
- Multi-PSV has no explanatory note.
- Only API 614 and the greeting canvas demonstrate cases.
- The notes don't say what to look at after running.
- Examples run pipes at 7–8 m/s without comment.
- There is a stray `walflow-diagram (8).wlf` in the examples folder.

**F3-16 – Pump "Off" still passes 0.3 L/min with equal tank heads.**
- Expected: 0 L/min.
- Likely cause: the regularised off-pump resistance.
- Physics nit; cross-reference Phase 1 pump findings.

**F3-17 – Pipe class concept not explained.**
- Rating, design temperature and corrosion allowance are shown but not used or checked.
- "TR2000" is not explained.
- The data list's schedule dropdown offers only STD/40/80/XS/160, even though the catalogue has 10S/40S and others.

**F3-18 – Discoverability.**
- No empty-canvas hint.
- No right-click menus.
- Rotation and copy/paste are documented only in the help modal.
- The ↻ rotate handle appears on selection, which is good.

**F3-19 – Version labels.** The UI shows App v0.2.0 / Format v0.2. AGENTS.md says 0.1.6 / 0.1, and `GreetingCanvas.wlf` has `app_version: 0.1.6`. One of them needs updating; this is the user's call per the versioning policy.

## What works well
- Drag-and-drop, equipment search and port connection: a first circuit takes under a minute.
- Operating Cases Matrix (KPIs with deltas, Batch Solve) and the Case Variable / Overridden / Reset badges.
- Pipe inspector results (pressures, ΔP, velocity, Reynolds number with regime, gradient).
- Piping Classes page layout.
- Autosave with the restore toast; fast solver (4–32 ms for these networks).
- Keyboard shortcut list in help; sidebar organised into tabs.
